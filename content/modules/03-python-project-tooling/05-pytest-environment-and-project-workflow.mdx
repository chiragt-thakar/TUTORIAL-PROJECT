## Tests describe behavior

pytest discovers `test_*.py` files and plain `test_*` functions. Use direct `assert` statements; pytest rewrites them to show useful differences. One test should establish a clear state, perform one behavior, and verify related outcomes.

```python title="tests/test_service.py"
import pytest

def test_complete_marks_existing_task_done() -> None:
    repository = InMemoryTaskRepository()
    task = repository.create("Ship API")
    service = TaskService(repository)

    completed = service.complete(task.id)

    assert completed.status is TaskStatus.DONE
    assert repository.get(task.id) == completed

def test_complete_rejects_unknown_id() -> None:
    service = TaskService(InMemoryTaskRepository())
    with pytest.raises(TaskNotFoundError, match="missing"):
        service.complete(TaskId("missing"))
```

Fixtures provide reusable setup through dependency injection. Prefer small fixtures with visible scope. A session-scoped mutable fake can leak state; function scope is the default for a reason. Parametrization is ideal when many inputs share one behavior.

## Configuration is input

Environment variables are process-level strings. Read them in one configuration boundary, convert them to typed values, and pass settings inward. Never read scattered environment values deep inside domain code.

Use `.env` for local convenience only when a settings loader explicitly supports it. Commit `.env.example` with safe placeholders; ignore `.env`; never place production secrets in source, tests, screenshots, or default values.

```python
import os

def require_database_url() -> str:
    value = os.environ.get("TASK_API_DATABASE_URL")
    if not value:
        raise RuntimeError("TASK_API_DATABASE_URL is required")
    return value
```

Later `pydantic-settings` will make typed configuration richer, but the architectural rule stays the same.

## The developer contract

Document exact commands and keep them boring:

```bash
uv sync --locked
uv run ruff format --check .
uv run ruff check .
uv run mypy src tests
uv run pytest
```

Run commands from repository root. CI should use the same lock and commands. A task runner is optional; add one only when it reduces real repetition.

<CommonMistake>

Tests that depend on your shell's existing environment can pass locally and fail in CI. Set configuration explicitly with pytest's `monkeypatch` and remove it after the test automatically.

</CommonMistake>

<ProductionNote>

Fail fast on missing required configuration at application startup, but avoid importing settings as a global singleton in modules that tooling and tests need to import independently.

</ProductionNote>

## Exercises

<Exercise id="tooling-tests-1">

Parametrize title validation over an empty string and whitespace-only strings.

<Solution>

```python
@pytest.mark.parametrize("title", ["", " ", "\n\t"])
def test_create_rejects_blank_title(title: str) -> None:
    with pytest.raises(ValueError, match="title is required"):
        InMemoryTaskRepository().create(title)
```

</Solution>
</Exercise>

<Exercise id="tooling-tests-2">

Test a required environment function without changing the developer's real environment permanently.

<Solution>

```python
def test_database_url_is_required(monkeypatch: pytest.MonkeyPatch) -> None:
    monkeypatch.delenv("TASK_API_DATABASE_URL", raising=False)
    with pytest.raises(RuntimeError):
        require_database_url()
```

pytest restores the environment after the test.

</Solution>
</Exercise>

<Exercise id="tooling-tests-3">

A test asserts a private `_tasks` dictionary. Improve it.

<Solution>

Assert through public behavior: retrieve the task, list tasks, update it, or expect a not-found error. Testing the private representation prevents safe refactoring without proving more user-visible behavior.

</Solution>
</Exercise>

</Checkpoint>

## Summary

pytest rewards simple tests and explicit fixtures. Environment variables belong at one configuration boundary. A short, locked validation sequence becomes the shared developer and CI contract.
