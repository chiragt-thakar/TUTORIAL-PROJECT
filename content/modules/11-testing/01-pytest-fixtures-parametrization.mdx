## Tests describe observable behavior

Use arrange-act-assert and name the condition and result:

```python
def test_complete_rejects_an_already_completed_task():
    task = Task(title="Ship", completed=True)
    with pytest.raises(AlreadyCompleted):
        task.complete()
```

Fixtures supply reusable state through dependency injection. Keep them small and return values rather than hiding assertions or many unrelated setup steps.

```python
@pytest.fixture
def task() -> Task:
    return Task(title="Ship")
```

Parametrization expresses the same rule over multiple cases:

```python
@pytest.mark.parametrize(("title", "valid"), [("Write", True), ("", False), ("   ", False)])
def test_title_rule(title, valid):
    assert Task.is_valid_title(title) is valid
```

Common mistakes are fixture chains nobody can read, mutable session-scoped state, tests that verify implementation details, and one test containing several behaviors.

## Production note

Tests must be deterministic: freeze time or inject a clock, seed randomness, and never depend on execution order.

Good pytest suites are explicit specifications made economical by small fixtures and meaningful case tables.
