## Make change boundaries visible

A practical request path is `router -> service -> repository -> database`. Schemas translate HTTP data, domain objects hold business rules, and ORM models represent persistence. They may be combined in a small CRUD service; split them when their reasons to change diverge.

```python
class CreateTask:
    def __init__(self, tasks: TaskRepository, uow: UnitOfWork):
        self.tasks, self.uow = tasks, uow

    async def execute(self, command: CreateTaskCommand) -> Task:
        task = Task.create(command.title, command.project_id)
        await self.tasks.add(task)
        await self.uow.commit()
        return task
```

The composition root creates concrete infrastructure and supplies it at the edge. Business code depends on narrow protocols, not FastAPI's `Depends` or a global session.

## Common mistakes

Avoid routers containing transactions and rules, repositories returning HTTP exceptions, generic `BaseService` hierarchies, and one interface per class with no alternative or test seam.

## Production note

Trace ownership of a transaction and an error from one file. If that requires jumping through ceremonial wrappers, simplify.

## Checkpoint

You can assign HTTP, policy, transaction, and storage responsibilities without inventing layers preemptively.

## Summary

Architecture is useful when boundaries isolate real changes and tests. Explicit wiring keeps those dependencies inspectable.
