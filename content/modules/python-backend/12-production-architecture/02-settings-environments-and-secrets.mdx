## Validate configuration at startup

Treat environment values as untrusted input:

```python
class Settings(BaseSettings):
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")
    environment: Literal["development", "test", "production"] = "development"
    database_url: PostgresDsn
    jwt_secret: SecretStr
    allowed_origins: list[AnyHttpUrl] = []
```

Create settings once in the composition root and inject them. Avoid reading environment variables throughout business code. Commit `.env.example` with names and fake placeholders, never real values.

Separate configuration that changes by environment from code. Fail startup when required values are missing, reject permissive production defaults, and ensure secret representations are redacted in logs.

## Common mistakes

Boolean strings parsed by hand, a wildcard CORS setting with credentials, test configuration reaching shared services, secrets embedded in images, and logging the full settings object all create avoidable incidents.

## Production note

Use a managed secret store in a real environment, rotate credentials, and make rotation possible without changing source code.

## Checkpoint

You can define typed settings, isolate environments, and identify values that must never reach source control or logs.

## Summary

Configuration is an application boundary: parse once, validate early, inject explicitly, and redact secrets everywhere.
