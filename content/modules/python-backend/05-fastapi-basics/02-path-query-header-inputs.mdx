## Sources come from the signature

A name present in the route path is a path parameter. Scalar parameters not in the path are usually query parameters. Use `Header()` for headers and `Annotated` to keep the Python type separate from FastAPI metadata.

```python
from typing import Annotated, Literal
from uuid import UUID
from fastapi import Header, Path, Query

@app.get("/projects/{project_id}/tasks")
async def list_tasks(
    project_id: Annotated[UUID, Path()],
    status: Annotated[Literal["open", "done"] | None, Query()] = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 50,
    x_request_id: Annotated[str | None, Header()] = None,
) -> dict:
    ...
```

FastAPI converts a UUID string or returns a 422 validation response. Header parameter underscores map to hyphens by default, so `x_request_id` reads `X-Request-Id`.

## Required, optional, and repeated values

As in Pydantic, a default controls omission and a union with `None` controls nullability. Query strings do not normally carry JSON null; absence maps to the default. A `list[str]` query parameter can collect repeated keys when declared with `Query()`.

```python
tags: Annotated[list[str] | None, Query()] = None
# ?tags=backend&tags=urgent
```

Path parameters are always required. Validate format in the type or declarative constraints; perform resource existence and authorization in dependencies or services.

<TypeScriptComparison>

Express exposes stringly typed `req.params`, `req.query`, and `req.headers`. FastAPI uses the signature to extract, convert, validate, document, and type those sources before your function runs.

</TypeScriptComparison>

<CommonMistake>

Do not accept pagination without upper bounds. A client-controlled `limit=1000000` can turn a valid endpoint into a memory and database incident.

</CommonMistake>

<ProductionNote>

Treat correlation IDs as untrusted strings: validate length and allowed characters, or generate a new value. Never reflect arbitrary header content into logs without structured encoding.

</ProductionNote>

## Exercises

<Exercise id="api-inputs-1" difficulty="easy">

Add an `offset` query parameter from 0 through 10,000 with default 0.

<Solution>

```python
offset: Annotated[int, Query(ge=0, le=10_000)] = 0
```

</Solution>
</Exercise>

<Exercise id="api-inputs-2" difficulty="medium">

Declare a required `If-Match` header as a string.

<Solution>

```python
if_match: Annotated[str, Header()]
```

With no default it is required, and the underscore maps to a hyphen.

</Solution>
</Exercise>

<Exercise id="api-inputs-3" difficulty="hard">

Add a repeated `tags` query parameter (`?tags=backend&tags=urgent`) alongside the existing bounded `limit`/`offset`, capped at 5 tags of 1–30 characters each, defaulting to no filter.

<Solution>

```python
tags: Annotated[list[str] | None, Query(max_length=5)] = None
```

`Query(max_length=5)` on a `list[str]` bounds the number of repeated keys, not the string length of each one; per-item length needs each tag validated separately (for example with a small `Annotated[str, Query(min_length=1, max_length=30)]` item type, or a dependency that checks the parsed list). The key discipline is the same as `limit`: an unbounded repeated parameter is still an unbounded parameter.

</Solution>
</Exercise>

<Exercise id="api-inputs-4" difficulty="interview">

Interview-style: "Why shouldn't a path UUID's database existence check be implemented as a field validator?" Answer in three sentences or fewer.

<Solution>

A field validator's job is deterministic input validation — confirming the string has the shape of a UUID — which requires no I/O and always gives the same answer for the same input. Whether that UUID actually identifies a row is a fact about current database state, not about the input's shape, and checking it requires I/O plus request context like authorization.

Mixing the two turns a fast, pure parsing step into a slow, stateful one and moves an application concern into a place designed for schema-level rules — that lookup belongs in a dependency or service instead.

</Solution>
</Exercise>

<Exercise id="api-inputs-5" difficulty="real-world">

Your logging pipeline choked after ingesting a request whose `X-Request-Id` header contained embedded newlines and text crafted to look like separate log entries, which a downstream log parser then split into forged-looking lines. Using only what this lesson covers, fix the endpoint.

<Solution>

The header was accepted as an unconstrained string and reflected straight into structured logs, so attacker-controlled content shaped the log stream. Constrain the header's accepted characters and length declaratively (for example `Header(max_length=64, pattern=r"^[A-Za-z0-9-]+$")`), rejecting anything that doesn't look like a correlation ID with a normal 422 before it ever reaches a log call.

Where the header isn't required to round-trip a client-supplied value, it's simpler and safer to ignore the incoming header and generate a fresh server-side ID instead — never trust an untrusted string enough to log it unvalidated.

</Solution>
</Exercise>

<Gotchas>

<Gotcha question="Does an unset query parameter arrive as JSON `null`?">

No — an absent query key simply means the parameter wasn't provided, so its declared default applies. Query strings have no native `null`; nullability and "was this key present" are handled the same way they are in Pydantic models, through separate default and type-union decisions.

</Gotcha>

<Gotcha question="Can a path parameter be made optional by giving it a default value?">

No — every name that appears in the route path is required by definition, because the route wouldn't match the request at all without it. A default on a path parameter is either ignored or a modeling mistake; make it a query parameter instead if it needs to be optional.

</Gotcha>

<Gotcha question="Does `Header()` read the header name exactly as written in your function's parameter?">

Not by default — FastAPI converts a parameter name's underscores to hyphens when matching header names, so `x_request_id` reads the `X-Request-Id` header. This is convenient once you know it, but surprising the first time a header "isn't arriving" during local testing.

</Gotcha>

</Gotchas>

<Checkpoint>

You can predict which request source supplies every parameter and where conversion ends and application lookup begins.

</Checkpoint>

## Summary

FastAPI signatures are executable request contracts. Use typed path values, bounded query parameters, explicit headers, and move I/O-dependent rules beyond validation.
