## Turn the specification into evidence

Create a traceability table connecting each requirement to at least one test. Use unit tests for domain and permission decisions, PostgreSQL integration tests for repositories and constraints, and API tests for validation, auth, serialization, and error contracts.

High-value cases include duplicate email, cross-project assignment, forbidden membership changes, expired tokens, stable pagination ties, transaction rollback, concurrent conflicting updates, secret-field exclusion, and migration-from-empty.

Every request receives a bounded correlation ID. Logs record event, outcome, actor/resource identifiers where safe, duration, and error code. Expected domain failures use controlled log levels; unexpected failures capture a stack trace but return the standard generic envelope.

## Production note

Coverage percentage is a clue, not acceptance. Review untested risk and mutation/change survival rather than chasing lines with trivial assertions.

## Checkpoint

Every frozen acceptance rule maps to executable evidence and every failure can be correlated without exposing sensitive data.

## Summary

Quality is a linked chain from requirement to test to observable runtime outcome—not a single coverage number.
