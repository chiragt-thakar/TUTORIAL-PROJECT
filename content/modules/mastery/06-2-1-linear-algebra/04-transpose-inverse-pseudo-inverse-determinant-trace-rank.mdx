Transpose, inverse, pseudo-inverse, determinant, trace, and rank are the compression of a matrix
into a few facts about the map it represents. Three are matrices, three are numbers, and all six
have a clean geometric meaning that the textbook formulas hide.

Two of them — the inverse and the determinant — are also the operations beginners reach for and
production code should not. Knowing the safe substitute for each is as important as knowing the
definition.

<TypeScriptComparison>

- Transpose in NumPy is `A.T`, a free view that just swaps the stride order; no data moves until something forces a copy.
- TypeScript has no matrix type, so a transpose is a manual reindex of `number[][]`, and an inverse or determinant is a from-scratch algorithm.
- `Math` has no `inv` or `det`; the naive recursive determinant is `O(n!)` and unusable past tiny sizes, which is a good reminder that `np.linalg.det` uses LU instead.
- `A.T @ A` is a common idiom in both worlds; in NumPy it is one call, but it squares the condition number, which the type system will never warn you about.

</TypeScriptComparison>

## Transpose is the adjoint for the dot product

The transpose `A.T` is defined by one identity: `dot(A @ x, y) == dot(x, A.T @ y)` for all `x, y`.
It is the matrix that lets you move `A` from one side of a dot product to the other. Everything else
about transpose follows from this.

Concretely `A.T[i, j] = A[j, i]`, so rows become columns. The column space of `A` becomes the row
space of `A.T`, `(A @ B).T == B.T @ A.T`, and a matrix with `A == A.T` is symmetric, which is the
condition that makes its eigenvectors orthogonal.

```python
import numpy as np

A = np.random.default_rng(0).standard_normal((3, 4))
x = np.random.default_rng(1).standard_normal(4)
y = np.random.default_rng(2).standard_normal(3)
assert np.isclose(np.dot(A @ x, y), np.dot(x, A.T @ y))   # the defining identity
assert np.array_equal((A.T).T, A)
```

## Inverse undoes the map, when that is possible

`A_inv` is the matrix with `A @ A_inv == A_inv @ A == I`. It exists only when `A` is square and
full rank — equivalently non-zero determinant, equivalently no zero singular value, equivalently a
trivial null space. All of those say the same thing: the map loses no information, so it can be run
backwards.

For a product, `(A @ B)_inv == B_inv @ A_inv`: undo the last map first. To undo a rotation you
rotate the other way; to undo a scaling you divide.

```python
A = np.array([[2.0, 1.0],
              [1.0, 3.0]])
A_inv = np.linalg.inv(A)
assert np.allclose(A @ A_inv, np.eye(2))

singular = np.array([[1.0, 2.0],
                     [2.0, 4.0]])   # row 2 = 2 * row 1
try:
    np.linalg.inv(singular)
except np.linalg.LinAlgError:
    pass   # no inverse: the map collapses the plane to a line
```

<CommonMistake>

Writing `np.linalg.inv(A) @ b` to solve `A x = b`. It is slower and less accurate than
`np.linalg.solve(A, b)`, which does the elimination once without ever forming the inverse. Forming
`A_inv` is only justified when you genuinely need the matrix itself, which is rare.

</CommonMistake>

## Pseudo-inverse solves the problem the inverse cannot

When `A` is not square or not full rank, there is no `A_inv`, but there is a best available
substitute: the Moore-Penrose pseudo-inverse `A_pinv`. Build it from the SVD `A = U S V.T` as
`A_pinv = V S_plus U.T`, where `S_plus` inverts the nonzero singular values and leaves the zeros
alone.

`A_pinv @ b` returns the least-squares solution to `A x = b` — the `x` that minimises
`norm(A @ x - b)` — and among all such minimisers it returns the one with smallest norm. For full
column rank it is a left inverse; for full row rank it is a right inverse.

```python
A = np.array([[1.0, 1.0],
              [1.0, 1.0],
              [0.0, 1.0]])          # 3x2, full column rank, no square inverse
b = np.array([2.0, 0.0, 1.0])
x = np.linalg.pinv(A) @ b
# same as the least-squares solution
x_ls, *_ = np.linalg.lstsq(A, b, rcond=None)
assert np.allclose(x, x_ls)
```

<WhyItMatters>

Linear regression's normal-equation solution `(X.T X)_inv X.T y` is exactly `X_pinv @ y`, and every
warning about multicollinearity is a warning that `X` is near rank-deficient so the small singular
values in `S_plus` blow up. Ridge regression floors those singular values, which is why it
stabilises the fit.

</WhyItMatters>

## Determinant is the signed volume factor

`det(A)` is the factor by which `A` scales signed volume: map the unit cube and measure. It equals
the product of the eigenvalues, the product of the pivots from elimination, and it is zero exactly
when `A` is singular. Key identities: `det(A @ B) == det(A) * det(B)` and `det(A.T) == det(A)`.

Do not compute it by cofactor expansion — that is `O(n!)`. `np.linalg.det` runs an LU factorisation
and multiplies the pivots, which is `O(n^3)`. For many uses you want `slogdet`, which returns the
sign and the log magnitude and does not overflow for large matrices.

```python
A = np.random.default_rng(3).standard_normal((5, 5))
sign, logabs = np.linalg.slogdet(A)
assert np.isclose(sign * np.exp(logabs), np.linalg.det(A))
# a probability-model log-likelihood needs log|det|, not |det|
```

## Trace is the sum of the diagonal and of the eigenvalues

`trace(A)` is the sum of the diagonal entries, and it also equals the sum of the eigenvalues. It is
invariant under a change of basis, `trace(P_inv @ A @ P) == trace(A)`, and it has the cyclic
property `trace(A @ B @ C) == trace(B @ C @ A)`.

The cyclic property is a workhorse. It lets you compute `trace(A @ B)` as `np.sum(A * B.T)` without
forming the product, and it turns many matrix-calculus derivatives into one-liners. Note
`trace(A @ B)` is not `trace(A) * trace(B)` in general.

```python
A = np.random.default_rng(4).standard_normal((4, 4))
B = np.random.default_rng(5).standard_normal((4, 4))
assert np.isclose(np.trace(A @ B), np.sum(A * B.T))       # cyclic + definition
assert np.isclose(np.trace(A @ B), np.trace(B @ A))
```

## Rank is the dimension of the image

`rank(A)` is the number of independent columns, which equals the number of independent rows, which
equals the number of nonzero singular values. It bounds what the map can do: `rank(A @ B)` is at
most the smaller of the two ranks, and a full-rank square matrix is exactly an invertible one.

On measured data rank is a tolerance question. `np.linalg.matrix_rank` counts singular values above
a threshold; the default is tuned for rounding noise, not for data noise, so set it from the
spectrum when screening features or weights.

```python
A = np.random.default_rng(6).standard_normal((6, 3))
B = np.random.default_rng(7).standard_normal((3, 6))
assert np.linalg.matrix_rank(A @ B) <= 3                  # capped by the shared dimension
```

## Doing this in floating point

The inverse, determinant, and exact rank are all fragile near singularity. `inv` of an
ill-conditioned matrix returns garbage in the last digits; `det` scales with the entries so it
tells you nothing scale-free; exact rank flips between values as a singular value crosses the
tolerance.

The SVD is the stable common ground. Singular values give a scale-free conditioning measure
`s[0] / s[-1]`, a tolerant rank, and the pseudo-inverse in one decomposition. When a linear-algebra
result looks wrong, compute the SVD of the inputs before anything else.

```python
ill = np.array([[1.0, 1.0],
                [1.0, 1.0 + 1e-12]])
s = np.linalg.svd(ill, compute_uv=False)
assert s[0] / s[1] > 1e11                                 # inv and det are both unreliable here
assert np.linalg.matrix_rank(ill, tol=1e-9) == 1
```

<ProductionNote>

Replace `inv(A) @ b` with `solve(A, b)`, `det(A) == 0` tests with a condition-number check, and
`(X.T X)_inv X.T y` with `lstsq` or `pinv`. Log `slogdet` instead of `det` for likelihoods, and log
the singular value spectrum whenever a fit or a solve misbehaves.

</ProductionNote>

## Cost

Creating `A.T` in NumPy is normally an `O(1)` strided view, but consuming that non-contiguous view
may require a copy or use a slower memory-access pattern; a transpose is therefore not universally
free end to end.

Trace is `O(n)`. Determinant, inverse, and a linear solve are all
`O(n^3)`, but the solve has the smallest constant and the best stability because it stops after
elimination. Rank and pseudo-inverse go through the SVD at `O(m*n*min(m, n))`.

If you need to apply `A_inv` to many right-hand sides, factor once with `scipy.linalg.lu_factor`
and reuse it, rather than forming `A_inv` or re-solving from scratch each time. For a symmetric
positive definite `A`, a Cholesky factor is twice as fast and more stable.

## Exercises

<Exercise id="la-tir-transpose-identity" difficulty="easy">

Verify by hand for `A = [[1, 2], [0, 1], [3, 1]]` that `dot(A @ x, y) == dot(x, A.T @ y)` with
`x = (1, 1)` and `y = (1, 0, 2)`.

<Solution>

`A @ x = (1*1 + 2*1, 0*1 + 1*1, 3*1 + 1*1) = (3, 1, 4)`. Then `dot(A @ x, y) = 3*1 + 1*0 + 4*2 =
11`.

`A.T = [[1, 0, 3], [2, 1, 1]]`, so `A.T @ y = (1*1 + 0*0 + 3*2, 2*1 + 1*0 + 1*2) = (7, 4)`. Then
`dot(x, A.T @ y) = 1*7 + 1*4 = 11`.

Both sides equal `11`, confirming the defining identity of the transpose on this example.

</Solution>
</Exercise>

<Exercise id="la-tir-when-inverse-exists" difficulty="medium">

List four equivalent conditions for a square matrix `A` to be invertible, and for
`A = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]` decide invertibility using the one that is cheapest to check
by hand.

<Solution>

`A` is invertible if and only if any one of these holds (and then all do): the determinant is
nonzero; the rank equals `n`; the null space is `{0}`; no singular value is zero; the columns are
linearly independent; `A x = b` has a unique solution for every `b`.

For this `A`, the cheapest by-hand check is linear dependence of the rows. Row 3 minus row 2 is
`(3, 3, 3)`, and row 2 minus row 1 is also `(3, 3, 3)`, so `row3 - row2 == row2 - row1`, i.e.
`row1 - 2*row2 + row3 == 0`. The rows are dependent, so the rank is 2, not 3, and `A` is singular
and not invertible.

</Solution>
</Exercise>

<Exercise id="la-tir-pseudo-inverse-from-svd" difficulty="hard">

Given `A = U S V.T` with singular values `s = (4, 2, 0)`, write `A_pinv` in terms of the SVD
factors, and explain what happens to the zero singular value and why.

<Solution>

`A_pinv = V S_plus U.T`, where `S_plus` is the transpose of `S` with each nonzero singular value
replaced by its reciprocal and each zero left as zero. Here `S_plus` has diagonal `(1/4, 1/2, 0)`.

The zero singular value corresponds to a direction that `A` maps to nothing — it lies in the null
space of `A` and outside the column space. There is no information to invert along it, so `S_plus`
puts a zero there rather than a blow-up.

Concretely, `A_pinv @ b` drops the part of `b` outside the column space of `A` — that part is
unreachable and becomes the residual — and it returns the minimum-norm `x` by placing nothing along
the null-space direction.

Numerically you replace "exactly zero" with "below a tolerance times `s[0]`", because measured
singular values are never exactly zero.

</Solution>
</Exercise>

<Exercise id="la-tir-interview-inv-vs-solve" difficulty="interview">

In an interview: "Why is `np.linalg.solve(A, b)` preferred over `np.linalg.inv(A) @ b`, and when
would you ever compute the inverse?"

<Solution>

`solve` does one LU factorisation of `A` and a triangular back-substitution, which is about `n^3/3`
operations and numerically stable. `inv(A) @ b` computes the full inverse — effectively `n` solves,
`n^3` operations — then does an `n^2` matrix-vector product, so it is roughly three times the work
and accumulates more rounding error, especially when `A` is ill-conditioned.

For many right-hand sides against the same `A`, you still would not form the inverse: factor once
with `lu_factor` and call `lu_solve` per right-hand side, or use Cholesky if `A` is symmetric
positive definite.

You compute the inverse only when the entries of `A_inv` are themselves the answer — for example a
closed-form covariance of estimated parameters, `sigma^2 * (X.T X)_inv` — and even then you often
extract just the diagonal from a factorisation instead.

</Solution>
</Exercise>

<Exercise id="la-tir-realworld-logdet" difficulty="real-world">

A Gaussian log-likelihood needs `log|det(Sigma)|` for a `500 x 500` covariance `Sigma`. Computing
`np.log(np.linalg.det(Sigma))` returns `-inf`. Explain and fix.

<Solution>

`det(Sigma)` is the product of 500 eigenvalues, each perhaps around `0.1` to `10`. Multiplying
hundreds of sub-unit values underflows to `0.0` in float64, so `np.log(0.0)` is `-inf`. The
determinant magnitude is simply not representable, even though its logarithm is a moderate number.

Use `sign, logabs = np.linalg.slogdet(Sigma)` and take `logabs` directly; it accumulates the log of
each pivot and never forms the underflowing product. Assert `sign > 0` for a valid covariance.

Better still, since `Sigma` is symmetric positive definite, take its Cholesky factor `L` and use
`2 * np.sum(np.log(np.diag(L)))`, which is faster, guaranteed real, and doubles as the factor you
need for the quadratic term `x.T @ Sigma_inv @ x` via a triangular solve.

</Solution>
</Exercise>

## Gotchas

<Gotchas>

<Gotcha question="`A.T` for a complex matrix — is that the right transpose?">

Usually not. For complex data you almost always want the conjugate transpose `A.conj().T` (NumPy's
`A.conj().T` or `.H` in some libraries), because the dot product that defines the adjoint is the
Hermitian one. Plain `.T` skips the conjugation and breaks the inner-product identity.

</Gotcha>

<Gotcha question="I need to solve `A x = b` for 1000 different `b`, so I should compute `A_inv` once.">

Factor once instead. `lu_factor(A)` then `lu_solve` per right-hand side is as reusable as the
inverse, faster, and more accurate. Forming `A_inv` costs more and adds error with no upside.

</Gotcha>

<Gotcha question="`trace(A @ B) == trace(A) * trace(B)`?">

No. Trace is linear and cyclic, so `trace(A @ B) == trace(B @ A)`, but it does not factor over a
product. `trace(A @ B) == np.sum(A * B.T)` is the useful identity.

</Gotcha>

<Gotcha question="`matrix_rank` says full rank, so the matrix is safely invertible.">

The default tolerance only rejects rounding-level singular values. A matrix can be "full rank" by
that test and still have a condition number of `1e10`, making its inverse meaningless. Check
`s[0] / s[-1]`, not just the rank.

</Gotcha>

<Gotcha question="The pseudo-inverse is just a slower inverse I can always use.">

For an invertible square `A`, `pinv(A)` does equal `inv(A)`, but via an SVD, which is several times
slower. Use `pinv` when there is no true inverse — non-square or rank-deficient — and `solve` or a
factorisation otherwise.

</Gotcha>

</Gotchas>

## Summary

Transpose is the adjoint for the dot product: the matrix that moves `A` across an inner product, and
the source of `(A @ B).T == B.T @ A.T` and of symmetry. The inverse undoes a map and exists only for
square, full-rank matrices; in code you solve or factor rather than invert.

The pseudo-inverse, built from the SVD, is the least-squares and minimum-norm answer when no inverse
exists, and it is what linear regression actually computes. Determinant is the signed volume factor
and the product of eigenvalues, but it is scale-dependent and underflows, so use `slogdet`.

Trace is the sum of the diagonal and of the eigenvalues, basis-invariant and cyclic. Rank is the
image dimension, and on real data it is a tolerance on the singular values, not an exact count.

The SVD unifies conditioning, rank, and the pseudo-inverse, and is the tool to reach for when any of
these misbehaves. The Practice, Debug, Interview, Test, Project, and Review tabs push on the safe
and unsafe ways to compute each.
